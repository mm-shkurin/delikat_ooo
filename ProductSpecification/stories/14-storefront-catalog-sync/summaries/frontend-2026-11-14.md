# Story 14 — frontend delivery

### 2026-11-14 — Deep link is a query, not a hash

- Type: decision
- Note: Buyer product link is `/catalog?product=<id>`. Hash stays `#sale`. Open writes the query; refresh runs a new detail GET. An already open panel is not invalidated (no poll/focus/SSE).

### 2026-11-14 — Panel copy is not the cart sentence

- Type: invariant
- Note: Panel text is exactly `товар не найден` (lowercase, no period) only for HTTP 404 or `product_not_found`. Other failures stay `Не удалось открыть карточку.` Cart keeps `failureText` → `Товар не найден.`

### 2026-11-14 — StrictMode aborted the only detail GET

- Type: mistake
- Note: A `requestedId` guard skipped the retry after StrictMode aborted the in-flight GET, so the panel stuck on `Загрузка карточки…`. The GET now lives in the search effect: cleanup abort always starts the next run.

### 2026-11-14 — Leaving the product layer drops the query

- Type: quirk
- Note: Address or cart replaces `layer === 'product'`. The hook then deletes `?product=` so a refresh does not reopen a panel that is already gone.

### 2026-11-14 — Compose build from this OneDrive tree fails

- Type: quirk
- Note: `docker compose up --build` dies with `invalid file request` on OneDrive reparse points (`frontend.dev.Dockerfile`, then `frontend/.env` / `.env.example`). `COMPOSE_BAKE=0` still used Bake. Images were built from a temp copy of the tree and `compose up -d` recreated frontend and backend. `.dockerignore` excludes `**/.env` and `**/.env.local`. Vite in the bind mount did not see edits until `compose restart frontend`.
