# Staff: заказы — список и статусы

## Brief Description

Owner, manager и cashier на `/admin/orders` видят все заказы магазина и двигают статус по цепочке. Имя и почта — снимок с оформления, телефона нет.

## Flow

1. Staff открывает `/admin/orders` — один GET всех заказов, новые сверху.
2. Фильтр и поиск режут уже загруженный список и новый запрос не шлют.
3. Select предлагает текущий статус и `allowed_next`. Успешный PATCH подставляет карточку из ответа.
4. Новое оформление без Bearer пишет «Гость». С живым Bearer пишет имя и почту один раз.
5. Повтор своего ключа идемпотентности возвращает строку как в базе. Чужой ключ по-прежнему 409.

## Acceptance Criteria

- Вкладка «Заказы» у owner, manager и cashier. Все трое одинаково читают список и меняют статус. ACL **12** не меняется.
- Нет токена, протухший `GET /staff/me` и 403 не-staff — ворота, вкладка не смонтирована. Тексты ворот: «Войдите через Яндекс ID — роль подтянется с сервера.» и «У этого аккаунта нет доступа в кабинет. Нужна роль сотрудника.» GET или PATCH на уже открытой вкладке умерли сессией — «Сессия истекла. Войдите заново.», нового редиректа нет. 403 на открытой вкладке — фраза про роль, не «Не получилось. Попробуйте ещё раз.»
- GET `/api/v1/staff/orders` без query и без страниц: `{ "items": [...] }`. Порядок: `created_at` убывает, затем `order_id` как строка UUID `8-4-4-4-12` в нижнем регистре возрастает. Предела нет. Открытие вкладки — один GET. Следующий GET только при новом заходе. Сокета, poll и SSE нет.
- `StaffOrder` и тело PATCH 200 всегда содержат только эти поля: `order_id`, `status`, `allowed_next`, `total_rub`, `created_at`, `buyer_name`, `buyer_email` (null, если нет), `customer_note` (null, если нет), `fulfillment` (`mode` `delivery`|`pickup`, `address.city`, `address.street_line`), `lines` (`product_id`, `product_name`, `weight_label`, `quantity`, `unit_price_rub`, `line_total_rub`) по возрастанию id вставки. Телефона нет. На карточке не показывать город, `product_id`, `unit_price_rub`, `allowed_next`.
- PATCH `/api/v1/staff/orders/{order_id}`, тело `{ "status" }`. `allowed_next`: шаг вперёд, если есть, затем `cancelled`, если можно. У `done` и `cancelled` пусто. Цепочка: `accepted` → `packing`|`cancelled`; `packing` → `ready`|`cancelled`; `ready` → `done`|`cancelled`. Версии и условного заголовка нет: последняя запись побеждает.
- Select с подписью «Статус»: текущий, затем `allowed_next` без второй сортировки. Пустой массив выключает select. Успешный переход и тот же статус — 200 и эта карточка. Отказ и обрыв возвращают select на прежний статус. Отмена — это `cancelled`, причину не спрашивать.
- 409 `invalid_status_transition`: и `message` тела, и вкладка — «Этот статус отсюда не поставить.» Пустое тело, нет `status`, неизвестный `status`, тело не объект — 400 `validation_error`, «Некорректный статус.» Не-UUID в path — 400 `validation_error`, «Некорректный номер заказа.» 404 `order_not_found` — «Заказ не найден.» Карточка остаётся до следующего успешного GET, select на прежний статус. Лишние поля игнорируются. Сеть и 5xx на GET и PATCH — «Не получилось. Попробуйте ещё раз.» Эта фраза не подменяет 400/404/409.
- До успешного GET нет счётчика и нет «Заказов нет». После успеха счётчик всегда «{показано} из {всего}», «всего» = `items.length`. Ноль показанных — ещё и «Заказов нет».
- Подписи `accepted` Принят, `packing` Собираем, `ready` Готов, `done` Выдан, `cancelled` Отменён — на фильтре, в select и на пилюле. Фильтр: Все, затем эти пять. По умолчанию Все, отменённые видны. Фильтр и поиск новый GET не шлют.
- Поиск без регистра, подстрока: полное `order_id`, первые 8 символов канонической строки, `buyer_name`, `buyer_email` только если не null, `customer_note`, `street_line`. Город не ищется. Края строки поиска срезаются; пустое после среза, в том числе одни пробелы, ничего не режет. Плейсхолдер «Номер, имя, почта».
- Заголовок — `buyer_name`. Под ним время (`ru-RU`, день 2-digit, месяц short, часы и минуты 2-digit, пояс браузера), « · », затем «Доставка» для `delivery` или «Самовывоз» для `pickup`, и если улица после trim не пустая — « · » и улица. Сумма — `total_rub`, целые рубли, `ru-RU` и « ₽». С почтой `{buyer_email} · № {первые 8 символов order_id в нижнем регистре}`. Без почты `№ {те же 8 символов}`. Комментарий только если после trim не пуст. Строка: `{product_name} · {weight_label} × {quantity} — {line_total_rub}` с тем же форматом рублей, что у суммы карточки. Состав — снимок заказа.
- Пилюля: текст на `--surface`, рамка `--border`, без заливки. accepted `--text`, packing `--accent`, ready `--success`, done `--text-muted`, cancelled `--danger`.
- Cookie shop-сессии на `POST /orders` обязательна. Authorization необязателен. Нет заголовка — «Гость», `buyer_email` null, статус `accepted`. Верный Bearer — `buyer_name` = trim показанного `display_name` витринного `GET /me`, не `provider_display_name`; пустое после trim — «Гость»; почта — email. Неверный или просроченный Bearer на первом POST и на повторе ключа — 401, строка не создаётся и не меняется. Живой вход шлёт Bearer тем же обновлением токена, что прочие входные запросы. Снимок после первого успеха не переписывается. Старые заказы без снимка — «Гость» и null.
- Повтор ключа в той же shop-сессии — 201 и строка как в базе, снимок не меняется. Другая shop-сессия — 409 `idempotency_conflict`. `message` заморожен, чек показывает его и после отмены. Ответ `POST /orders` и лист чека не получают `buyer_name` и `buyer_email`. Чек только после 201, статус не рисует, JSON `status` принимает пять значений. Мёртвый вход и 401 оформления — «Сессия истекла. Войдите заново.» в корзине, чек не открывается, гостевой POST из мёртвой ветки не уходит.
- На 390px поиск, фильтр и select остаются в панели. Успешный PATCH не обновляет Статистику и Деньги: они остаются каркасом. Заказ из кабинета, сброс демо и правка состава не входят. Новых токенов, hero и адресного chip нет.

## Validation Rules

| Состояние | Правило |
|-----------|---------|
| переход | только цепочка выше; тот же статус — 200 |
| чужой статус | 409, прежний статус на экране |
| path не UUID | 400 «Некорректный номер заказа.» |
| нет / кривой status | 400 «Некорректный статус.» |
| нет заказа | 404 «Заказ не найден.» |
| Bearer оформления | нет — гость; верный — снимок; плохой — 401 |

## Screen States

- Ворота **12**, вкладки нет.
- Вкладка грузится: без счётчика и без «Заказов нет».
- Список: карточки, счётчик, фильтр. Пустой фильтр — «Заказов нет» и «0 из N».
- Ошибка загрузки или записи. Select терминального статуса выключен.

## Core Requirements

- Контракт списка и PATCH — `admin_api.yaml`. Пять статусов `OrderCreated.status` — `store_api.yaml`.
- Состав, сумма, адрес и комментарий этой историей не переписываются.
- Демо-пароль `staff` и `localStorage` мокапа не используем.
