# Staff: категории каталога (CRUD + порядок)

## Brief Description

Owner и manager на `/admin/categories` создают категорию, меняют название и порядок, удаляют категорию вместе с её товарами. Витринный сайдбар держит этот порядок и обновляется сигналом без F5. Cashier вкладку не видит.

## Flow

1. Owner или manager открывает `/admin/categories` — список всех категорий по `sort_order`, затем `id`.
2. «Добавить» / правка → диалог. Id только при создании. Название 1…120 после срезания краёв.
3. «Выше» / «ниже» и перетаскивание сразу пишут полный порядок. На ширине ≤ 420px перетаскивания нет.
4. «Удалить» спрашивает подтверждение с тем же числом товаров, что в строке, включая скрытые.
5. Успешная запись шлёт открытому каталогу сигнал. Сайдбар и сетка перечитываются. Панель товара не трогается.
6. Cashier не видит вкладку; `/admin/categories` открывает заказы. Staff-пути категорий без права → 403, без токена → 401.

## Acceptance Criteria

- Вкладка «Категории» сразу после «Каталог»: owner и manager. Id маршрута `categories`.
- Строка: id, название, `sort_order`, число всех SKU категории (скрытые входят). Пустой список: «Категорий нет», кнопка «Добавить» на месте.
- Create: id `^[a-z][a-z0-9-]{0,31}$`, уникален, не `all`. Название непустое после trim, не длиннее 120, без обрезки. Одинаковые названия можно. Новая категория в конце сайдбара: пустая таблица получает `sort_order` 1, иначе max+1 в той же записи. Дырку после удаления не заполняем.
- Ошибки у полей до запроса и с сервера, строка при отказе не пишется. Кривой id — 400 `validation_error`, текст «Некорректный код категории.» Пустое название — «Введите название.» Длиннее 120 — «Название не длиннее 120 символов.» Занятый id — 400 `category_id_taken`, «Такая категория уже есть.» Id `all` — 400 `category_id_reserved`, «Код all занят кнопкой «Все».», это не кривой id и не занятый.
- Edit: id только показан. Меняется название.
- Порядок пишется сразу полным списком id. Кнопки «Сохранить» нет. Первая «выше» и последняя «ниже» запрос не шлют. После успешной записи видимые номера строк — 1…N в новом порядке.
- Ширина окна ≤ 420px — только кнопки. Шире — кнопки и перетаскивание.
- Удаление одной операцией стирает категорию и все её товары. Диалог: «Удалить категорию «{title}» и {n} товаров?», кнопки «Удалить» и «Отмена». Последнюю категорию удалить можно: в сайдбаре остаётся «Все», каталог пустой.
- Переименование или удаление уже отсутствующей категории — 404 `category_not_found`, текст «Категория не найдена.» остаётся на списке. Диалог закрывается, список читается заново. Успешная перечитка не подменяет этот текст фразой «Не получилось. Попробуйте ещё раз.»
- Сбой запроса, отказ порядка и ошибка загрузки списка показывают «Не получилось. Попробуйте ещё раз.» Отказ порядка — 400 `validation_error`, строки возвращаются на последний принятый порядок.
- Заказы, строки корзины, смена количества и checkout не меняются. Новый add отсутствующего id — «Товар не найден.» Освободившийся id товара можно занять снова.
- Публичный GET категорий без Bearer и без счётчика. Тело: `id`, `title`, `sort_order`. Пустая категория остаётся кнопкой сайдбара и открывает «Ничего не нашлось. Снимите часть фильтров.» «Все» только на клиенте и в query не уходит.
- Уже открытый каталог после успешной записи категории обновляет сайдбар и сетку без F5. Сигнал уходит, когда запись уже видна следующему GET. Кадр `{ "type": "catalog_changed" }` без товаров, без `hidden` и без счётчиков.
- После сигнала и после повторной подписки одно поколение: незавершённые GET категорий, товаров и «Показать ещё» отменяются, ответ старого поколения не применяется. Сначала GET категорий. Если выбранного id нет, фильтр становится «Все» и `category_id` не уходит. Затем GET товаров: `offset=0`, `limit` = max(16, сколько карточек уже показано), не больше 100. Цена, свойства, sort и `#sale` остаются.
- Если GET товаров вернул 400 по выбранному id, фильтр становится «Все», список читается без `category_id`. Экран «Каталог сейчас недоступен.» из этого пути не ставится.
- Обрыв сокета: витрина подписывается снова и читает каталог тем же порядком.
- Уже открытая панель товара от сигнала не закрывается и сама не перечитывается. Следующее открытие, deep-link `?product=` и обновление detail стёртого id — «товар не найден».
- Hide, цена, имя и плашка одного SKU сами на витрину не толкаются.
- Неизвестный или кривой `category_id` в списке товаров — 400 `validation_error`, пустой список не отдаём.
- Форма товара при открытии заново читает публичный GET категорий. В select только его items. «Все» в select нет.
- Вкладка выглядит как соседние разделы кабинета: те же tabs, диалог и ширина 420px. Новых токенов, hero, адресного chip и картинки категории нет. Toolbar-фильтр категории в списке SKU не появляется.
- ACL остальных вкладок из **12** не меняется. Owner: Каталог, Категории, Заказы, Статистика, Деньги, Сотрудники. Manager: Каталог, Категории, Заказы, Сотрудники. Cashier: только Заказы.
- Шесть seed-категорий из `catalog-categories.json` не защищены. Счёт «7 категорий» из истории **02** сюда не переносить.
- `site/` не переводим на API.

## Validation Rules

| Field / State | Rule |
|---------------|------|
| role | owner \| manager; cashier и не-staff → 403; нет токена → 401 |
| id create | `^[a-z][a-z0-9-]{0,31}$`; не `all`; unique; кабинет показывает ошибку до запроса; сервер не пишет строку |
| id `all` | 400 `category_id_reserved` |
| id taken | 400 `category_id_taken` |
| id shape / title | 400 `validation_error` |
| missing category | patch и delete → 404 `category_not_found`, «Категория не найдена.»; диалог закрыт; список заново |
| delete | одна операция: нет категории — нет её товаров |
| id edit | показан, не меняется |
| title | trim; 1…120; внутренние пробелы живы; длиннее не обрезаем |
| duplicate title | разрешён |
| product_count | все SKU категории, скрытые входят; только staff-список |
| delete n | то же число, что в строке, включая 0 |
| order body | все текущие id ровно один раз; иначе 400 `validation_error`, текст «Не получилось. Попробуйте ещё раз.», строки на последний принятый порядок |
| live refresh | отменить GET категорий, товаров и «Показать ещё»; старое поколение не применять; сначала категории; нет id → «Все» без `category_id`; затем товары `offset=0`, `limit` = max(16, показано) ≤ 100; 400 по выбранному id → «Все» и повтор без `category_id`; экран «Каталог сейчас недоступен.» не ставить |
| socket drop | подписаться снова и пройти тот же порядок |
| public category | `id`, `title`, `sort_order`; без счётчика и без Bearer |
| sort_order | уникален; пустая таблица → 1; иначе max+1 в той же записи, дырку не заполнять; перестановка пишет 1…N и эти номера видны в строках |
| public list | `sort_order`, затем `id` asc |
| narrow | ширина ≤ 420px без drag |
| buyer category_id | существующий id или omit; кривой и неизвестный → 400 `validation_error` |
| open panel | не инвалидируется этим сигналом |

## Screen States

- `/admin/categories`: список | «Категорий нет» | ошибка загрузки — «Не получилось. Попробуйте ещё раз.»
- Диалог create/edit с ошибками у полей. Диалог удаления.
- Cashier: вкладки нет; чужой адрес открывает заказы.
- `/catalog`: кнопки сайдбара, включая пустую категорию. «Все» первая, только на клиенте.

## Core Requirements

- Id категории — `catalog_categories.id`. Второй колонки slug нет.
- Staff-пути только в `admin_api.yaml` под `/api/v1/staff/catalog/...`.
- Сигнал витрины — WebSocket без staff-токена, кадр `{ "type": "catalog_changed" }`, после того как запись видна следующему GET. В кадре нет товаров, нет `hidden` и нет счётчиков.
- Узкая отмена **14**: сигнал только на create / rename / reorder / delete категории. Poll, SSE и focus-revalidate не добавляем.
- Шесть seed-категорий из `catalog-categories.json` не защищены. Семёрку из истории **02** не переносить.
