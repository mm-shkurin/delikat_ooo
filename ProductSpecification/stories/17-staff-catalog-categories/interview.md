# Interview — 17 Staff: категории каталога (CRUD + порядок)

**Статус:** подтверждено. Сборка спек запущена без новых вопросов; дыры sources закрыты решениями ниже.  
**Волна:** Wave 3, backlog после **13**.  
**Зависит от:** **12** (shell, ACL, staff Bearer), **09** (категории и `sort_order`), **13** (товары и select категории), **14** (витрина читает live-каталог; открытая панель товара не обновляется сама).  
Acceptance на категории staff нет. Опора: живой кабинет `frontend/` и витрина `/catalog`. `site/admin` — только референс вкладок и диалогов, не новый контрол.

## Scope

**IN:**

- Вкладка **Категории**, id `categories`, маршрут `/admin/categories`, сразу после «Каталог».
- Owner: `catalog`, `categories`, `orders`, `stats`, `money`, `employees`. Manager: `catalog`, `categories`, `orders`, `employees`. Cashier вкладки нет; `/admin/categories` → `/admin/orders`.
- Создать категорию, переименовать `title`, менять порядок. `id` только при создании. Отдельной колонки slug нет: id и есть код категории.
- Удалить категорию вместе с её товарами из каталога. Последнюю тоже можно.
- Кнопки категорий в сайдбаре фильтров витрины идут по `sort_order`. Пустая категория — такая же кнопка.
- Успешная запись категории толкает уже открытый каталог без F5. Правка одного SKU из **13** и уже открытая панель товара остаются как в **14**.
- Публичный `category_id` — любой существующий `catalog_categories.id`, не закрытый enum из шести slug.

**OUT:**

- `site/` и `fetch` в мокапе. Новая полоса чипов. Токены, hero, адресный `.nav-chip`.
- Poll, SSE, focus-revalidate. Сокет не заменяет **14** для hide/edit одного товара.
- Смена id после создания. Уникальность названия. Картинка категории. Фильтр категории в списке SKU.
- Удаление одного товара с вкладки Каталог. Чистка корзины и заказов. Запрет смены количества и checkout по снимку.
- Заказы **15**, статистика и деньги **16**.

## Pages / Surfaces

- `frontend/` — `/admin/categories`.
- Диалог создания и переименования. Отдельный диалог удаления.
- Витрина `/catalog`: кнопки `.cats` в сайдбаре. «Все» только на клиенте и в query не уходит.
- Форма товара: select категорий, список заново при открытии диалога.
- Запись: `admin_api.yaml`, `/api/v1/staff/catalog/...`.
- Публичный список, фильтр и сокет: `store_api.yaml`.
- Узкая ширина кабинета уже ломается на **420px** (`frontend/src/styles/admin.css`). Drag пропадает на этой границе, не на 390.

## Content & Assets

- Поля строки: `id`, `title`, `sort_order`, число всех товаров категории, включая скрытые. Число только в staff-списке.
- Seed — шесть названий из `catalog-categories.json`. Они не защищены. Счёт «7 категорий» из истории **02** сюда не переносить.
- Новая категория встаёт в конец. Если строк нет, `sort_order` = 1. Иначе номер берётся в той же записи, что и вставка, и два одновременных создания не получают один `sort_order`. `sort_order` уникален. Публичный список: `sort_order`, затем `id` по возрастанию. Перестановка переписывает номера с 1 по N.
- Пустой staff-список не прячет «Добавить». Текст: «Категорий нет».
- Пустая категория на витрине открывает уже существующий текст «Ничего не нашлось. Снимите часть фильтров.»
- Вкладка выглядит как остальные разделы кабинета.

## Key Decisions

- `DECISION:` Создать, переименовать название, менять порядок. Id только при создании.
- `DECISION:` Id категории = `catalog_categories.id`. Шаблона второго slug нет. На редактировании id только показан.
- `DECISION:` Id: `^[a-z][a-z0-9-]{0,31}$`, уникален. `all` создавать нельзя — это клиентская кнопка «Все». Отказ отдельный, не кривой id и не занятый: код `category_id_reserved`, текст у поля «Код all занят кнопкой «Все».»
- `DECISION:` Название после срезания краёв — от 1 до 120 символов (колонка `title` уже String(120)). Пробелы внутри сохраняются. Длиннее 120 не обрезаем и не пишем. Пусто после среза — «Введите название.» Длиннее 120 — «Название не длиннее 120 символов.» Обе ошибки у поля названия.
- `DECISION:` Одинаковые названия можно. Занятый id — **400** `category_id_taken`, текст «Такая категория уже есть.», ошибка у поля id, без overwrite. Id `all` — **400** `category_id_reserved`, текст у поля «Код all занят кнопкой «Все».»
- `DECISION:` Кривой id, пустое и слишком длинное название кабинет показывает у поля до запроса. Сервер такое не пишет и отвечает **400** `validation_error`. Кривой id на сервере — тот же текст «Некорректный код категории.»
- `DECISION:` Удаление стирает категорию и все её SKU из каталога, скрытые тоже. Заказы и корзину не трогать. Диалог: «Удалить категорию «{title}» и {n} товаров?» `{n}` — то же число, что в staff-строке, скрытые входят. Ноль остаётся в той же фразе. Кнопки «Удалить» и «Отмена».
- `DECISION:` Последнюю категорию удалить можно.
- `DECISION:` Id удалённого товара свободен. Вкладка Каталог может создать товар с этим id снова (**13**). Уже лежащая строка корзины не пересчитывается. Смена количества и checkout идут со снимка, как сейчас. Нельзя только новый add, пока такого товара нет: уже существующий `product_not_found`.
- `DECISION:` Вкладка «Категории» у тех же ролей, что Каталог. Owner и manager делают одно и то же. Cashier не видит вкладку. Любой новый staff-путь категорий, включая чтение списка со счётчиком, — owner|manager; cashier и не-staff → **403**. Без токена → **401**.
- `DECISION:` Публичный GET категорий без Bearer и без счётчика скрытых. Форма: `id`, `title`, `sort_order`.
- `DECISION:` Пустая категория остаётся в публичном GET и в сайдбаре. Отдельного клиентского фильтра «спрячь пустые» нет. Это решение интервью, когда вопрос ушёл на выбор без нового раунда, и сборка спек идёт с ним.
- `DECISION:` Порядок меняют кнопки «выше» / «ниже» и перетаскивание. Оба сразу пишут полный порядок id. Кнопки «Сохранить» нет. «Выше» на первой и «ниже» на последней ничего не отправляют.
- `DECISION:` Перетаскивание ставит строку на новое место. Ширина окна **≤ 420px** — только «выше» и «ниже». Шире — кнопки и перетаскивание.
- `DECISION:` Создание и переименование — диалог. Ошибки у полей. Сбой запроса — уже общий текст «Не получилось. Попробуйте ещё раз.»
- `DECISION:` Запись в `admin_api.yaml` под `/api/v1/staff/catalog/...`.
- `DECISION:` Витрина при записи категории обновляется сама. Это узкая отмена правила **14** «без realtime»: только успешные create / rename / reorder / delete категории. Hide, цена, имя и плашка одного SKU по-прежнему ждут новый GET. Poll, SSE и focus-revalidate не добавляем.
- `DECISION:` Канал — WebSocket без staff-токена, только сигнал `{ "type": "catalog_changed" }`. В кадре нет товаров, нет `hidden`, нет счётчиков.
- `DECISION:` Сигнал уходит только после того, как запись уже видна следующему GET. Одно поколение чтения: незавершённые GET категорий, товаров и «Показать ещё» отменяются. Ответ старого поколения не применяется. Сначала GET категорий. Если выбранного id нет, фильтр становится «Все» и `category_id` в запрос товаров не уходит. Затем GET товаров: `offset=0`, `limit` = max(16, сколько карточек уже показано), не больше 100. Цена, свойства, sort и `#sale` не сбрасываются. Если GET товаров всё же вернул 400 по выбранному id, фильтр становится «Все», список читается без `category_id`, экран «Каталог сейчас недоступен.» из этого пути не ставится.
- `DECISION:` Неизвестный или кривой `category_id`, если его всё же прислали в публичный список, — **400** `validation_error`. Пустой список из-за этого не отдаём. `all` в query не шлём.
- `DECISION:` Уже открытая панель товара от сигнала не закрывается и сама не перечитывается (**14**). Следующий open / deep-link / refresh detail для стёртого id даёт «товар не найден».
- `DECISION:` Обрыв сокета: витрина подписывается снова и читает каталог тем же порядком, что после сигнала.
- `DECISION:` Форма товара при открытии заново читает публичный список категорий.
- `DECISION:` `site/` не переводим на API. Toolbar-фильтр категории из мокапа в список SKU не копировать.

## Behavior & Rules

- Полный порядок — все текущие id, каждый один раз, без чужих. Иначе **400** `validation_error`. Кабинет возвращает строки на последний принятый порядок и показывает «Не получилось. Попробуйте ещё раз.»
- Удаление и переименование отсутствующей категории — **404** `category_not_found`, текст «Категория не найдена.» Диалог закрывается, список читается заново. Удаление одной операцией: нет категории — нет её товаров.
- Owner и manager равны. ACL остальных вкладок из **12** не ломаем.
- Шесть исходных категорий — обычные строки.

## Already Implemented (REUSE)

- Кабинет `/admin/:tab`, роли, `resolveAllowedTab` — **12**. Чужая вкладка cashier уходит на `orders`.
- `catalog_categories`: `id` String(32), `title` String(120), `sort_order`. Публичный GET по `sort_order`.
- Сайдбар витрины рисует кнопки из GET и добавляет «Все».
- Форма товара берёт тот же GET. Select есть.
- `shop_order_lines` и `cart_lines` хранят копию имени и цены, без внешнего ключа на товар.
- Новый add отсутствующего товара уже даёт `product_not_found`. Checkout и смена количества живой товар не проверяют.
- Неизвестный `category_id` у staff-товара — `category_not_found`.
- Сокета в коде нет. Уже открытая панель товара сама не инвалидируется.

## NOT Yet Implemented (Gaps)

- Истории **15** и **16**.

## Integrations

## Check Notes

- Переименовать → сайдбар и select товара показывают новое название. Id в диалоге не меняется.
- Порядок кнопками и перетаскиванием при ширине больше 420px. На 420px и уже только кнопки, порядок всё равно пишется сразу.
- Удаление: диалог с числом, товары пропадают из каталога и из сетки. Старая строка заказа на месте. Новый add этого id, пока товар не создан снова, — «Товар не найден.» Количество в корзине и checkout не ломаются.

- Две категории с одним названием и разным id живут рядом. Id `all` не создаётся.
- Cashier вкладки не видит, `/admin/categories` открывает заказы. Staff-пути категорий → 403. Без токена → 401.
- Обрыв сокета не оставляет сайдбар на старом списке после повторной подписки.
- Скрытый товар и staff-счётчик в кадр сокета не попадают.
