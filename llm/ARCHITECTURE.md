# Работа с моделью

Слой взят из `adaptive-tutor`: доменный `LLMService` и адаптер `FreeLLMAPIClient`. Чат через этот код реально ходит в модель. Поиск по документам и эмбеддинги в этих двух файлах не реализованы — они описаны в спеке adaptive-tutor и вызываются снаружи.

## Слои

```
вызов (чат / квиз / объяснение / RAG-ответ)
        │
        ▼
LLMService                         llm/domain/llm_service.py
  знает сценарии, не знает HTTP
        │  llm_client.chat_completion(...)
        ▼
FreeLLMAPIClient                   llm/infrastructure/freellmapi_adapter.py
  OpenAI SDK, base_url по умолчанию http://localhost:3001/v1
        │
        ▼
freellmapi                         роутер на провайдера, модель "auto" или имя модели
```

Ключ читается из `FREE_LLM_API_KEY` или передаётся в конструктор. Без ключа клиент не создаётся.

Ответ адаптера: `content`, `model`, `usage` (prompt / completion / total tokens). Ошибка сети или API становится `RuntimeError`.

## Четыре сценария в LLMService

Все четыре в итоге зовут один `chat()`.

| Метод | Что делает | Параметры генерации |
| --- | --- | --- |
| `chat` | Сообщения `system` / `user` / `assistant` → текст | модель `auto`, temperature 0.7, max_tokens 1000 |
| `generate_quiz` | Просит JSON: question, 4 options, correct_answer 0–3, explanation. Контекст режется до 500 символов | temperature 0.5, max_tokens 1000 |
| `generate_explanation` | Текст объяснения, примеры по флагу. Контекст до 500 символов | temperature 0.6, max_tokens 800 |
| `rag_chat` | В промпт кладёт до 3 кусков уже найденного текста и последние 2 реплики истории. Система: отвечать только по контексту и цитировать источники | temperature 0.3, max_tokens 500 |

`generate_quiz` JSON не разбирает: возвращает сырой ответ в `[{"raw_response": ...}]`. `generate_explanation` кладёт весь ответ в `explanation`, список `examples` оставляет пустым.

`rag_chat` сам ничего не ищет. Куски текста должен принести вызывающий код.

## Как задумано до ответа (спека adaptive-tutor, этого кода нет)

Индексация идёт отдельно от чата, в фоне:

1. PDF читается (PyMuPDF), таблицы становятся Markdown.
2. Текст режется по абзацам и заголовкам, чанк не короче 500 токенов.
3. Эмбеддинги — тот же freellmapi, OpenAI-совместимый `POST /v1/embeddings`. В интервью размер вектора 384.
4. Векторы пишутся в свой Qdrant. Имя файла, дата, число чанков и статус — в PostgreSQL.
5. На вопрос: эмбеддинг запроса → поиск в Qdrant → список строк в `rag_chat`.

Отказ эмбеддинга останавливает документ. Ошибка сервера эмбеддинга укладывается в три попытки. Если настроек Qdrant нет, приложение не стартует.

## Чего в скопированном адаптере нет

- метода эмбеддингов;
- клиента Qdrant;
- разбора JSON квиза и примеров из объяснения;
- HTTP-эндпоинтов FastAPI — в adaptive-tutor они были только в гайде, не в этом слое.
